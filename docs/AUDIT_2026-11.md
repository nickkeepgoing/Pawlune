# Pawlune — Audit และแผนปรับ (26 พ.ย. 2569)

อ้างอิงงาน: "Research-Driven Product Refinement" ตำแหน่งใหม่คือ **More Than Adoption. A Better Bond.** และปัญหาหลักคือ **The Adoption Compatibility Gap**

## 1. สภาพโค้ดตอนนี้

| ด้าน | สิ่งที่มี |
|---|---|
| Framework | Next.js 15 (App Router, server actions), React 19, Tailwind v4, TypeScript strict |
| Backend | Supabase: Postgres + RLS, Auth (อีเมล/username/Google), Storage `pet-photos` (private) |
| Migrations | 0001 init → 0003 username/avatar → 0004 trial/ST-5/shelter |
| Roles | ผู้ใช้ทั่วไป, `is_shelter` (เจ้าหน้าที่ศูนย์), `is_demo` มี trigger กันผู้ใช้ตั้งค่าให้ตัวเอง |
| Engine | TS ล้วน มีเทสต์เทียบ reference Python (`npm run test:engine`) |
| Flow หลัก | สมัคร → ยินยอม → อายุ 20+ → (มีสัตว์ / กำลังหา) → จับคู่ → ขอทดลอง → ศูนย์อนุมัติ → 14 วัน → ตัดสินใจ → feedback รายเดือน / คืนศูนย์ |

### ฟีเจอร์ตามสถานะ
- **ใช้งานได้:** บันทึกรายวัน, รูปแบบ (patterns), WHO-5, ST-5, รายงานรูปภาพ, จับคู่ตามกฎ, ทดลอง 14 วัน, feedback วันที่ 14/รายเดือน, คืนศูนย์และจับคู่ใหม่, หน้าศูนย์, โปรไฟล์/avatar
- **ทำได้บางส่วน:** หน้าศูนย์ไม่มีขั้นตอนตรวจก่อนอนุมัติ, ไม่มีข้อมูลสุขภาพ/พฤติกรรมของสัตว์, ไม่มีข้อตกลงค่าใช้จ่ายและเหตุฉุกเฉิน
- **ยังไม่มี:** คืนก่อนครบ 14 วัน, ช่องทางแจ้งปัญหาระหว่างทดลอง, คู่มือแมว (ขนส่ง/ห้องปลอดภัย/สัญญาณอันตราย), เงื่อนไขแมวในบ้าน/สัตว์เดิมในบ้าน

## 2. ความเสี่ยงที่พบ (เรียงตามความรุนแรง)

1. **เจ้าหน้าที่ศูนย์เห็นคำขอของทุกศูนย์** และอนุมัติคำขอของศูนย์อื่นได้ เพราะ `is_shelter` เป็นสิทธิ์รวม → ต้องผูกเจ้าหน้าที่กับศูนย์
2. **ระหว่างทดลอง ผู้ใช้คืนน้องไม่ได้จนถึงวันที่ 14** ขัดหลัก "ไม่บังคับให้ทดลองต่อเมื่อคนหรือสัตว์มีความเสี่ยง"
3. **RLS ของ `trial_feedback` เป็น `for all`** ผู้ใช้แก้/ลบ feedback ที่ส่งศูนย์แล้วได้ และใส่ `trial_id` ของคนอื่นได้ (แม้ศูนย์อ่านผ่าน service role) → เปลี่ยนเป็นเพิ่มได้อย่างเดียว และต้องเป็นการทดลองของตัวเอง
4. **ขอทดลองสัตว์ที่ไม่ว่างหรือถูกตัดออกจากการจับคู่ได้** ถ้ายิง form ตรง (เช็กแค่ฝั่งหน้าจอ) → ตรวจซ้ำฝั่ง server และใน policy
5. **อนุมัติโดยไม่มีหลักฐานว่าศูนย์ตรวจแล้ว** → เก็บ `approved_at`, `approved_by` และรายการตรวจ

## 3. ส่วนที่ขัดกับกลยุทธ์ใหม่

| จุด | ปัญหา | แก้ |
|---|---|---|
| หน้า `/adopt/[id]` | "งานวิจัยพบว่าการได้ออกจากศูนย์ช่วงสั้นๆ ช่วยลดความเครียดของสุนัข" เป็นข้อมูลหมาและอ่านเหมือนการันตี | เขียนใหม่เป็นข้อเท็จจริงเรื่องคืนได้โดยไม่ผิด |

| การจับคู่ | ไม่มีเรื่องแมวในบ้าน มุ้งลวด สัตว์เดิมในบ้าน | เพิ่มกฎแบบเปิดเผย (ไม่ใช่ AI) |
| Demo | การทดลองของบัญชี demo เป็นหมา (ถั่วแดง) | **คงไว้** เพราะ fixture บันทึก 60 วันผูกกับเทสต์ engine; เพิ่มแมวในรายชื่อให้มาก่อน แล้วเสนอเปลี่ยน demo เป็นแมวหลังเพิ่ม fixture ใหม่ |

## 4. หมา: ข้อเสนอที่เล็กที่สุดและปลอดภัย
ฐานข้อมูลรองรับ `dog | cat` อยู่แล้ว **ไม่ลบ** สิ่งที่ทำ:
- ค่าเริ่มต้นของผู้ใช้ใหม่เลือก "แมว" (เลือกหมาเพิ่มได้)
- รายชื่อเรียงแมวก่อนเมื่อคะแนนเท่ากัน
- คู่มือและข้อความเฉพาะสัตว์แสดงตามชนิด หน้าแรกบอกชัดว่า MVP เริ่มที่แมวในกรุงเทพฯ และปริมณฑล

## 5. แผนดำเนินการ

| ไฟล์ | เปลี่ยน |
|---|---|
| `supabase/migrations/0005_cat_first.sql` (ใหม่) | ฟิลด์แมวใน prefs/สัตว์, ข้อตกลงใน trials, `profiles.shelter_id`, RLS feedback, policy ขอทดลอง, kind `concern` |
| `lib/engine/match.ts` + tests | กฎ: สัตว์เดิมในบ้าน (ตัดออกถ้าศูนย์ระบุว่าไม่เข้ากัน), แมวเคยออกนอกบ้าน, คอนโดไม่มีมุ้งลวด |
| `app/(app)/adopt/*` | ฟอร์มความพร้อมแบบใหม่, เปิดเผยประวัติสุขภาพ/พฤติกรรม, ข้อตกลงก่อนขอ, ตรวจซ้ำฝั่ง server |
| `app/(app)/trial/*` | คืนก่อนกำหนด/แจ้งปัญหาได้ทุกวัน, การ์ดสัญญาณอันตราย, คำแนะนำตามช่วงวัน |
| `app/(app)/shelter/*` | กรองตามศูนย์, รายการตรวจก่อนอนุมัติ, เห็นข้อตกลงและเรื่องที่แจ้ง |
| `app/learn/cat/page.tsx` (ใหม่) | คู่มือ 14 วันแรกกับแมว: ขนส่ง ห้องปลอดภัย แนะนำสัตว์เดิม สัญญาณต้องไปหาหมอ |
| `app/page.tsx` | Positioning ใหม่ |
| Layout ทั้งหมด | Responsive: มือถือ → แท็บเล็ต → เดสก์ท็อป (เมนูบนสำหรับจอใหญ่) |
| `scripts/seed-demo.ts`, `fixtures/demo-trial.json` | ข้อมูลแมวตัวอย่างพร้อมประวัติ, ผูกเจ้าหน้าที่กับศูนย์ |

**ความเสี่ยงของ migration:** คอลัมน์ใหม่มีค่าเริ่มต้นทั้งหมด ไม่ทำให้ข้อมูลเดิมพัง การเปลี่ยน policy feedback ทำให้แก้ feedback เก่าไม่ได้ (ตั้งใจ) เจ้าหน้าที่ศูนย์เดิมต้องตั้ง `shelter_id` ใน SQL editor ไม่งั้นจะไม่เห็นคำขอ

**ทดสอบ:** `npm run test:engine` (เพิ่มเคสแมว), `npm run typecheck`, `npm run build`, ไล่ flow ตาม handoff/07_TEST_SHEET ที่เพิ่มข้อ 30–36

## 6. สิ่งที่ห้ามพูด (ยึดตามนี้ทั้งแอปและพิตช์)
- ไม่วางตัวเป็นการรักษาสุขภาพจิต ไม่บอกว่าสัตว์รักษาซึมเศร้าหรือทำให้ใจดีขึ้นแน่นอน
- ไม่บอกว่า 14 วันรับประกันว่าเข้ากันได้
- ไม่บอกว่าลดอัตราการคืนได้ จนกว่าจะมีข้อมูล pilot
- การจับคู่เป็น **กฎที่เปิดเผย** ไม่ใช่ AI
- สวัสดิภาพสัตว์สำคัญเท่ากับสุขภาวะคน
